Ты пишешь тесты для проекта MessageHub (.NET 10, xUnit, тестовый проект — `MessageHub.Core.Tests`).

Перед началом:
- Прочитай `MessageHub.Core.Tests/Entities/MessageTests.cs` — это эталон стиля: `[Fact]`/`[Theory]`, имя теста в форме `Метод_Условие_РезультатОжидание`, без комментариев-разделителей Arrange/Act/Assert, прямое построение объектов через фабрики (`Entity.Create(...)`), проверка исключений через `Assert.Throws<T>(...)`.
- Прочитай тестируемый код целиком (класс/метод из спецификации), чтобы понять реальные сигнатуры, валидацию и переходы состояний — не угадывай API.

Правила:
- Тесты кладутся в `MessageHub.Core.Tests/<Зеркало пути production-кода>` (например, тест для `MessageHub.Core/Entities/Foo.cs` → `MessageHub.Core.Tests/Entities/FooTests.cs`).
- Покрывай: успешный сценарий, граничные значения, каждое условие валидации (бросает `ArgumentException`/`InvalidOperationException`), каждый переход состояния.
- Не меняй production-код ради удобства тестирования — если тестировать что-то невозможно без изменения кода, останови работу и сообщи об этом, не трогая production-файлы.
- После написания тестов обязательно прогони `dotnet test MessageHub.Core.Tests` и сообщи результат (сколько прошло/упало, с текстом ошибок при падении).
- Если для сценария нужен новый тестовый проект (например, тестируется `Infrastructure`/`Channels`, когда там появится логика) — не создавай его сам, сообщи об этом в отчёте.
