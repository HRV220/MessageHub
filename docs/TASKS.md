# MessageHub — разбивка задач по ТЗ v2.1

Источник — `docs/TZ_Local_Messenger_Hub.md` (v2.1) и `docs/schema.dbml`. Задачи сгруппированы в **дорожки** (тема — от сущности/фичи до всех затронутых слоёв) и пронумерованы `T-NNN`. Оценка — 1–4 часа работы человека без ИИ.

## Как читать

- Каждая задача — чекбокс `- [ ] **T-NNN** ...`. Отмечайте `[x]` по мере выполнения.
- **(оценка ч, зависит: T-NNN, T-NNN)** — сколько по времени и от каких задач зависит (нельзя начинать раньше). `зависит: —` — можно начинать сразу.
- В конце строки — требования ТЗ для трассировки: US-XX / ФТ-XXX / АРХ-XX / БЗ-XX / НФТ-XX.
- Дорожки **0–2 обязательны первыми** для всех остальных (каркас решения, ревизия Core, порты Application).
- Дорожки **3–13** в целом идут по фиче, но внутри каждой порядок задач — Core/Application → Infrastructure/Channels → Api → UI → тесты. Дорожка 4 (каналы/Telegram) должна быть готова раньше дорожки 5 (кандидаты), 6 (лента) и 7 (единый чат), т.к. они читают то, что кладёт синхронизация.
- Дорожки **15–16** — в конце, после того как фичи готовы.

## Текущее состояние (на момент составления, 2026-09-23)

- Есть: `MessageHub.Core` — почти все сущности (`Person`, `ChannelContact`, `ConnectedAccount`, `Conversation`, `ConversationParticipant`, `Message`, `MergeProposal`, `RelationChangeLog`, `SyncState`, `UserProfile`) + тесты на часть из них.
- **Нет** проекта `MessageHub.Application` вообще (в ТЗ, раздел 6.2, он есть) — `MessageHub.Infrastructure`, `MessageHub.Channels`, `MessageHub.API` сейчас пустые заглушки (`Class1.cs` / шаблонный `WeatherForecast`), без DI и без связи с `Core`.
- Есть три известных расхождения между текущим кодом `Core` и ТЗ/schema.dbml, зафиксированы как отдельные задачи в дорожке 1: `ChannelType` — enum вместо VO (раздел 7.2), `UserProfile` — секретный вопрос вместо `password_salt`/`kdf_params` (раздел 8.3), `ConnectedAccount` — персистентные `SecretRef`/`LastError`, хотя секреты не должны сохраняться (БЗ-02).
